# 情境感知交互助手 · 一周电脑原型

这是比赛方案的第一阶段实现：摄像头或照片识别中文通知，用户确认后调用 DeepSeek 提取材料清单，再由用户逐项核对、撤销和保存结果。完成状态只表示用户核对完材料。

## 运行

需要 Node.js 20 或更新版本、网络连接、摄像头（也可选照片）和 DeepSeek API 密钥。

```powershell
npm install
Copy-Item .env.example .env
# 编辑 .env，填入自己的 DEEPSEEK_API_KEY
npm start
```

浏览器打开 `http://127.0.0.1:3000`。首次 OCR 运行时，Tesseract.js 需要下载中文识别模型并缓存，可能较慢。DeepSeek 只有在用户点击“确认并调用 DeepSeek”后才收到识别文字。也可以粘贴或修改识别文字，便于处理反光、模糊输入。

## Android 手机通过 USB 使用

手机开启 USB 调试并授权电脑后，保持电脑上的 `npm start` 运行，再在电脑终端执行：

```powershell
adb devices
adb reverse tcp:3000 tcp:3000
adb shell am start -a android.intent.action.VIEW -d http://127.0.0.1:3000/
```

在手机浏览器允许摄像头权限，点击“开启后置摄像头”，对准通知后点击“拍照识别”。页面只请求后置摄像头，无法调用时会报错而不会切到前置。识别仍在电脑上运行，USB 拔掉或电脑服务关闭后手机页面无法继续工作；这不是离线手机端 OCR。若 `adb` 不在 PATH 中，请使用 Android SDK Platform Tools 中的 `adb` 完整路径。

拍摄时让文字占据画面大部分，避免反光、倾斜和运动模糊。识别后核对页面中的拍摄预览及文字；低置信度结果会提示重拍或修改。OCR 会先识别原图，结果不稳时再尝试增强与高对比度版本。识别质量仍取决于实际文书和光照，建议保存失败照片用于针对性评估。

## 演示流程

1. 用 `samples/` 中的通知制作清晰图片，选照片或使用摄像头扫描。
2. 检查并修正 OCR 文字，确认整理清单。
3. 点击或滚动选择材料，双击切换已准备状态；键盘方向键与 Enter 也可使用。
4. 查看缺项、撤销确认、保存本次结果为本地 JSON。取消后旧请求不会刷新新任务。

## 验证

`npm test` 检查提示规则和材料依据校验。现场还需测试三份开发通知、两份独立通知、模糊照片、断网、取消和连续五次演示，并记录耗时及漏项。`samples/` 仅是开发示例，不能代替独立评估集。

## 当前边界

本原型通过鼠标、触控板或键盘模拟镜腿输入；材料由用户确认。未实现手机、眼镜、支付、语音、自动材料匹配或真实办理。结果中的原文依据仅做文字包含检查，仍需人工检查理解是否正确。密钥保存在本机 `.env`，该文件已被 Git 忽略。
